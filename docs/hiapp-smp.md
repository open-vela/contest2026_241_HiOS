# HiOS App 双核调度约定

本约定适用于当前 ESP32-P4、NuttX SMP（两核）及 HiOS App 宿主。

## SD 安装的 `.hiapp`

无需改变安装包格式或重新打包。现有及以后安装的 Lua 应用共用运行时，脚本、JavaScript 和解析工作在可由两个核调度的后台线程执行。图片解码、安装信息扫描和二维码识别使用相同后台策略。LVGL 创建、触摸事件及显示提交仍由原有界面线程处理。

`hios.cpu()` 返回当前 `cores`、`mask`、`cpu`、`policy`。两核可调度的线程 `mask` 为 3；`cpu` 只是调用瞬间所在核，不是核数。此接口用于能力查询，不应在 App 中频繁轮询。一个 Lua 会话仍只有一个 VM 执行线程，不能同时在两个核执行同一段 Lua；多个独立任务可以并行。

媒体控制、剪贴板及摄像头访问由系统接口转到对应所有者，应用不直接访问硬件或 LVGL。安装包原有网络、存储、摄像头权限和执行预算继续生效。

## 编译进 HiOS 的原生 App

HiOS App 宿主完成启动后，同进程中新建、未明确指定 CPU 的 `pthread_create` 和 `std::thread` 后台任务默认允许两核运行；默认调度为 RR、优先级 81。明确指定的 CPU 集合及显式调度参数仍有效。内核任务、启动任务和其它进程不受这条默认规则影响。

新原生 App 应在公共框架内接入，不要在 LVGL 事件回调中进行长时间计算。使用 `port/hi_task_policy.h`：

- `hi_task_create_compute`：普通后台计算或受锁保护的文件、网络处理，可调度至两核。
- `hi_task_create_legacy`：沿用第一核的硬件或兼容性任务；调用者已有明确 CPU 集合时予以保留。
- `hi_task_create_neural`：本地专用模型计算的固定第二核所有者。
- `hi_task_post_ui`：异步提交到原 LVGL 线程。参数须保持有效直至回调执行；检查返回值并管理参数释放。

使用消息、互斥锁、原子变量或不可变快照交接数据。不要让后台任务直接操作 LVGL 对象。使用 PIE、自定义硬件循环寄存器或不可重入外设的代码不能直接当作普通可迁移任务，必须使用明确所有者并审核中断/上下文规则。

已有音频、电话、蓝牙、4G、USB 和界面任务显式保留原约束。唤醒模型在第二核完成初始化和推理，音频回调回到原所有者。相机只在持有同一 RAW 帧的转换段开放后台调度，交还采集缓冲区前恢复原 CPU 集合，不改变像素算法、曝光、尺寸或帧所有权。

## 验收边界

双核调度不保证所有 App 有相同加速比，也不能缩短云端推理和网络等待。新原生 App 若绕开宿主另建独立进程，需要显式使用相同任务角色接口并单独验证。新驱动或新模型必须验证数据同步、优先级、堆栈及实际音视频表现；安装支持本身不构成所有第三方应用都没有问题的保证。
