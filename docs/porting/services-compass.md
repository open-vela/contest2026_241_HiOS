# 指南针、磁场与开放服务适配

此次修改保留定位、AI 生图、翻译、天气及智慧屏的既有页面布局。天气卡片仅更新现有控件的内容，翻译下拉箭头移除了不受字体支持的符号。指南针与磁场页按本次需求补充传感器行为和动效。

## AI 生图固件直连（2026-10-30 后续修改）

AI 生图页已改为设备通过 HTTPS 直连 AI Horde，独立于下述局域网适配器。设备使用匿名 API key，提交 `generate/async`，每隔约三秒查询 `generate/check/{id}`，完成后获取 `generate/status/{id}` 并下载 HTTPS 图片。接受 HTTP 202；支持 1–4 张、512×512 生成。退出页面、查询失败和超时会尝试 DELETE 取消未完成任务。其他功能仍保持原有服务连接。

AI Horde 的 WebP 图片在设备后台线程中解码，输出最长边 450 的 BGRA 像素供 LVGL 显示，不经过电脑转换。只接受最大 512×512 的静态 WebP，下载上限 800 KiB；过滤被审查的图片与非 HTTPS 下载地址。解码失败有明确提示。使用 libwebp 1.6.0 的纯 C 解码器，来源、原始哈希和 NuttX 枚举命名兼容补丁记录在 `apps/metalio/third_party/libwebp/upstream.json`，许可证和专利授权随源码保存。

文字描述直接提交给 AI Horde，不再调用电脑上的中文翻译模型；中文输入仍可提交，但建议英文以获得更稳定的提示词理解。AI Horde 不提供语音识别。默认主按钮为“输入描述”，打开系统输入法。若已有兼容云端识别服务，可在 Settings 的 `imagegen/asr_url` 保存完整 HTTPS URL：请求体为 16 kHz 单声道 WAV，返回 `{"code":0,"data":{"text":"识别结果"}}` 或 `{"code":0,"data":"识别结果"}`；配置后恢复“按住说话”。该接口当前仅支持无需额外鉴权头的兼容服务，未内置第三方语音凭证。

协议来源：[AI Horde 集成文档](https://github.com/Haidra-Org/AI-Horde/blob/main/README_integration.md)。解码接口：[Google WebP API](https://developers.google.com/speed/webp/docs/api)。测试脚本 `scripts/test_horde_direct.py` 编译实际生产协议代码与解码器，覆盖任务编号、错误、审查图片、URL、损坏与过大图片、缩放和颜色；`scripts/verify_horde_direct_live.py` 可复用一个真实匿名任务完成云端链路检查。新候选固件和验证记录保存在 `output/ai_horde_direct`，是否烧录以该目录记录为准，下方原发布记录不代表此次候选固件已烧录。

## 当前接入方式（其他功能及先前版本）

设备通过 `http://192.168.31.31:8766` 访问此电脑上的定位查询与默认语音识别兼容服务。天气改为设备直连 Open-Meteo；翻译 App 按用户最新要求仅保留界面，不发起录音或接口调用。生图任务已合并“AI生图”对话的直连方案，设备直接访问 AI Horde 并下载、解码 WebP，文字生图不经过电脑。原有 8765 生图服务不受影响。电脑与设备应在同一可互通的局域网；电脑服务停止时，依赖该兼容服务的功能会显示失败或保留标明为上次结果的天气。GPS 卫星坐标、指南针和磁场测量不依赖电脑服务。

服务脚本为 `scripts/hios_services.py`，使用独立的 `.venv-services` Python 环境。启动：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_hios_services.ps1
```

健康检查：`http://127.0.0.1:8766/health`。没有建立开机计划任务。电脑重启后可手动运行上述脚本。

设备默认地址位于 `apps/metalio/include/api_endpoints.h` 的 `CONFIG_METALIO_SERVICES_HOST`，也可由已有 Settings 存储的 `services/url` 覆盖。此地址独立于原有 OpenClaw、语音对话和 OTA 服务。电脑 IP 变化后必须相应更新，建议路由器固定 DHCP 地址。

## 天气

- 设备按保存的区划编号，直接向 DataV 行政区 GeoJSON 读取区县坐标与完整名称，只接收开头必要的 properties 对象，不下载整个边界多边形；验证返回编号与所选地区一致。
- 设备直接查询 [Open-Meteo 天气 API](https://open-meteo.com/en/docs)，获得当前天气、7 天预报和 48 小时逐小时数据。数据是气象模型估计，不是设备自身温度传感器测量。
- 主天气到达后立即发布给天气 App 与智慧屏；空气质量作为独立的可选直连请求，不阻塞温度、天气及预报显示。空气质量来源 CAMS / Open-Meteo，AQI 为美国标准。缺少的数据用 `--`，不编造生活指数或预警。
- 天气 App 和智慧屏共享一个后台服务；界面只读取快照。地区编号通过已有 Settings 保存，切换地区后核对请求与响应，避免上一地区的慢请求覆盖新选择。
- 成功后 10 分钟刷新，失败至少间隔 60 秒重试；同一启动内保留上次成功的天气并标注。坐标在工作线程内缓存，不反复写 flash。
- 智慧屏地区文字由 20 号改为 30 号，显示省级名称与完整区县名，例如“北京市海淀区”“广东省宝安区”。超过卡片宽度的名称在原位置滚动显示，卡片布局不变。
- 天气不再使用电脑兼容服务；免费公共源的可用性与额度依提供方规则。

## 定位

- 本机 GNSS 解析带校验和的 GGA、RMC、GSV；提供经纬度、高度、HDOP、速度和可见卫星数，读写状态加锁。超过 5 秒未更新的定位失效。未知信息不以零冒充有效测量。
- GPS 经纬度按 WGS84 传递给地图，修正旧请求将卫星坐标标为 GCJ02 的问题。
- Wi-Fi 与基站数据通过 [beaconDB](https://beacondb.net/) 查询。请求关闭 IP 兜底，避免把电脑出口 IP 所在城市当成设备定位。数据库覆盖有限，无覆盖可失败。
- 地址查询采用可配置、可自部署的 [Photon](https://github.com/komoot/photon)，默认公共演示服务；请求串行限速并缓存。公共服务不保证长期可用，地址语言由其数据决定。
- 地图按当前视野获取 OpenStreetMap 瓦片，不进行离线预下载。缓存至少七天，最多四个并行下载，图片内保留 `© OpenStreetMap contributors` 标注。地图生成失败不影响已取得的坐标。
- `HIOS_PHOTON_URL` 和 `HIOS_TILE_URL` 环境变量允许切换自部署或其它兼容服务。遵循 [OSM 瓦片使用规则](https://operations.osmfoundation.org/policies/tiles/)。

## 生图与翻译界面

- 生图已合并“AI生图”对话的固件直连方案：直接提交 [AI Horde](https://aihorde.net/) 免费匿名任务，接受 HTTP 202，轮询状态、下载 WebP 并在设备上解码；保留 1–4 张选择，最长边缩放到 450。
- 退出页面时尝试取消未完成任务；请求与页面会话绑定，旧结果不会写入新页面。结果下载单独使用 90 秒时限并重试一次，与小 JSON 请求的时限分开。
- 保留“按住说话”和“文字”两个入口，文字面板复用系统中文输入法。语音识别可用 Settings 的 `imagegen/asr_url` 指定 HTTPS 兼容接口；未配置时仍使用现有电脑上的 ASR 服务。文字生图不依赖电脑。
- AI Horde 不提供语音识别；默认识别由电脑 CPU 上的 faster-whisper 完成。设备将麦克风与回声参考的双声道数据分离，只上传真正的麦克风单声道；录音期间独占输入，结束时释放所有权。WAV 长度按真实样本计算。
- NuttX 的 pthread 封装任务通过函数返回释放 C++ 缓冲和录音保护对象；工作线程身份使用 `pthread_self()`，避免结束后仍占用任务句柄。
- 中文描述直接提交给 AI Horde，页面提示英文描述通常更合适。匿名队列有等待时间。
- 翻译 App 按用户最后要求保留图标、语言选择、原文／译文卡片和原有布局；录音、HTTP、WebSocket、识别和翻译服务调用全部移除。点击原按钮仅显示“翻译服务尚未接入”，不占用麦克风。

## 指南针与磁场

指南针使用 QMC6309 的磁场方向与 SC7A20H 的重力方向，保留已有板级轴约定。没有安装方向的实测依据，因此没有猜测交换芯片坐标轴。需实机验证屏幕方向与两颗芯片轴向的一致性。

新版校准要求三维翻转覆盖，旧水平校准不能提前结束三维校准。采样至少 80 个有效样本，重力覆盖三个轴的正反方向，并覆盖至少四个象限，避免六面动作被原先六象限门槛卡住。页面按不足的轴提示左右翻转、前后翻转或屏幕朝上再朝下；20 秒数据不足则结束等待并提示重新校准。重新校准期间保留上一份有效结果，只有新结果保存成功才替换。并非放置不动即可校准，自动测试不会替用户伪造翻转动作。

按各轴范围估计硬铁偏移与比例，校准结果持久化。此方法不等于完整的软铁椭球校准。校准不足、磁场异常、加速度异常、指向接近竖直时不继续显示有效航向。输出磁北，不宣称真北。

磁场页保留红 X、绿 Y、蓝 Z 卡片，三色条以零点为中心双向伸缩，白色游标跟随真实读数；采用三轴共用量程及平滑过渡，小幅变化更可见。数字约 10 Hz、动效约 30 Hz 更新，传感器读取在独立工作线程内，过期和溢出读数不作为有效数据。

## 验证与交付

- `scripts/test_compass_math.cxx`：方位、倾斜补偿、退化姿态、跨 0° 平滑及水平/三维校准。
- `scripts/test_gps_parser.py`：从实际驱动提取解析函数编译，验证校验和、GGA/RMC/GSV、无定位、过期定位及非法坐标。
- `scripts/test_hios_services.py`：协议、中文编码、输入边界、地图缓存、禁用 IP 伪定位和翻译会话收尾。
- `scripts/verify_hios_services_live.py`：真实天气、语音识别、语音到中文翻译、地址地图及 AI Horde 生图。
- 固件在 `/tmp/hios-services-compass/tree` 隔离构建；源码包、构建日志、检查结果、测试图片和候选固件位于 `output/services_compass`。

已完成两轮工程固件自动烧录和真机检查，合计 19 项检查通过。真机验证了图标拖动从第一页向左到最后一页再向右返回、顺序保持、小白条双向循环切换、真实传感器读取、天气联网和地区写入 Settings。第二轮的七张完整页面截图已检查，天气 App 与智慧屏内容一致，待机覆盖问题已消除。第一轮的图标拖动逻辑日志作为补充证据；不完整的桌面截图不作为截图验收依据。

正式固件关闭工程自测入口；最终烧录结果和启动日志由 `output/services_compass/delivery-result.json` 指向的发布目录保存。生产配置保持不变，应用固件增加 9,616 字节。烧录器备份设置区、核对烧录哈希和启动标记；发布检查还确认烧录前读取的实际设置区包含已保存的天气地区。

室内真机未取得有效卫星定位，GNSS 有效定位仍需室外条件；地址和地图后台另以真实坐标联网验证。指南针仍需手持设备进行三维翻转校准并检查安装轴向和整机磁干扰。麦克风实际采集、扬声器声学效果及完全断电后的地区恢复未由本次自动检查替代。

## 通话静音与切换

静音操作查询模组当前状态、执行 `AT+CMUT` 并读回核对；失败时不把按钮显示成已经静音。过滤上一次通话遗留的异步请求。当前 NT26 固件在空闲时拒绝该指令，因此空闲探测不能证明通话中可用；用户已指定真实通话静音由其手动验收，本次没有自动拨号。

桌面图标拖动与小白条切换均采用双向循环索引，处理首尾边界、空列表、单应用和队列失败。`scripts/test_navigation.py` 从实际实现提取代码进行检查；`scripts/check_call_audio_route.py` 覆盖静音读回、错误响应及原有通话音频路径。

## 水平仪、图标移动与全应用语音启动

水平仪校准采用一次三轴保存，存储在独立工作线程内完成，并在 flash 操作期间与 LVGL 绘制串行。该线程使用 16 KiB 栈；保存成功前不显示完成。弹窗减少大面积透明混合和阴影临时缓冲，布局与按钮位置不变。32 个样本要求实际有新数据，8 秒采样不足则提示重试。

图标移动已按用户最新要求恢复原来的紧凑排序与跨页方式，保留双向循环翻页；撤回“来源留空、只向后顺延”和新增页面逻辑。拖动开始时取消残留的点击动画定时器，编辑过程中不写入 flash。退出编辑后，后台合并保存，并与 LVGL 绘制串行，避免在对象拖动、重排时暂停外部存储缓存。

全部 37 个内置应用及已安装 SD 卡应用通过统一入口解析名称，处理打开前缀、空格、大小写、应用／软件后缀和标点；AI 应用列表包含 SD 卡应用与 `hiapp:` ID。未对用户撤回的“SD 图标不显示”另作修复。

自动构建先运行 `scripts/run_feature_checks.py`，包含：应用匹配、GPS、指南针、双向切换、通话音频、AI 麦克风声道与所有权、直连 Horde 协议／HTTP／WebP、直接天气解析，以及翻译调用代码已移除的检查。Windows 构建脚本同步功能源码列表并检查固件布局；烧录统一使用设置备份、哈希校验与启动验证。真实录音、图片显示、天气组件和拖动事件的设备验收记录保存在对应发布目录。

## 2026-10-31 补充实现

天气主请求改为设备直接访问 Open-Meteo；区县中心坐标从仓库已有 CSV 编译为设备内置的 3395 条经纬度记录，保留原编号与顺序；正常天气请求不需要在线地理编码。原 GeoJSON 解析仍作为无效坐标的备用路径。七日、48 小时与当前天气共用同一快照，空气质量单独补充，失败不清空已取得的温度。地区仍保存为六位行政区编号。智慧屏地区使用 30 px 字体，城市在上、县或区在下，不显示省，两行右对齐并留出卡片内边距。地区名称使用同编号的离线全称表，避免选择列表中省略“县／区”的短名。

AI 生图保留 AI Horde 设备直连、WebP 解码、文字和按住说话两个入口。英文描述直接提交；中文描述经 MyMemory 的公开 GET 接口分段转为英文供 Horde 使用，原中文仍在界面保留。该接口有免费额度限制，失败显示实际错误。生图录音独占麦克风后配置本机音频通路，提取麦克风声道、去直流偏置并按幅度适当增强；过轻录音提示重试。该采集修复仅由生图调用。翻译应用保留界面、删除录音和网络调用，语言互换按钮仍能交换两个语言选择。

生图数量选择器下箭头和翻译语言互换箭头改用原生线段绘制，避免字体缺字方框。生图首页文案改为 32 px 加粗“图片AI创意，由你定义！”。

桌面采用原紧凑重排和双向跨页，拖动到另一图标中心停留后松手可创建文件夹，或把应用加入现有文件夹。文件夹名称支持系统输入法中英文输入；点击名称修改；文件夹内长按进入拖动排序，选中应用后可点“移到桌面”，解散返回全部成员。文件夹及其成员和桌面顺序保存在同一有版本的设置项，先持久化成功再更新显示，保存失败保留原桌面。文件夹不限制语音打开成员和 SD 应用。移动编辑期间阻止系统边缘切换手势抢占拖动。

设备验收另存于对应发布目录；本说明中的实现描述不代替实机检查结果。通话静音仍按用户要求手动验收。

区县选择表补全全称时只替换名称，不重排或重编码 3395 条记录。离线映射固定在 `scripts/data/weather_district_full_names.json`，以 [DataV 全区划列表](https://geo.datav.aliyun.com/areas_v3/bound/all.json) 的同编号名称为主，缺失编号参考 [Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) 的 2023 年开放数据；原有特殊地区名称保留。`update_weather_district_names.py` 可离线重现，`test_weather_district_names.py` 检查全表与典型区、县、县级市、自治县，不会重复追加“区区／县县”。生图数量选择器使用显式居中、对称内边距与零列间距，1～4 共用同一显示区域，右侧原生下拉箭头独立绘制。

AI 生图单独通过 `?profile=imagegen` 使用 multilingual small / int8 识别配置，beam 5、固定温度、关闭跨段上下文累积，并调整 VAD 边缘保留。中文结果统一转为简体。其它 ASR 请求仍使用原配置；路由隔离和诊断音频的双重 opt-in 已由协议测试验证。诊断音频仅当工程固件标记与临时服务环境变量同时存在时保存，正式固件不发送该标记。麦克风输入租约取得后，仅在生图录音入口暂停本地音乐、电台和旧播放器，等待旧 PCM 排空，恢复输入时钟并预读两帧后才开始计时。

生图数量框将可见字形独立绘制，按实际 glyph 边界计算中心偏移，避免把字体基线中心当作数字中心。自动检查覆盖 1～4 的字形中心与框中心偏差。桌面短停留释放执行原紧凑重排，停留达到阈值后目标描边变绿、按钮提示“松手合并”，释放创建文件夹；使用拖动图标的视觉中心计算合并命中。自动验证覆盖完整长按、拖动、悬停和释放，以及 12 轮快速释放的真实 LVGL pointer 通路。智慧屏音乐入口绑定 `hi_music`；因歌曲恢复后会替换页面标题，跳转检查同时核对 dock 绑定和 Hi 音乐的实际控件。

工程测试临时隔离物理触摸、暂停自动闲置策略并移除待机覆盖层，测试结束恢复输入与闲置策略。此控制仅在工程固件中编译，不更改正式系统的待机策略。

最终交付按用户明确要求停止远距离／全零录音排查。未保留为此添加的强制蓝牙 RX／模式刷新。最终 ASR URL 拼接已修正为 `format=wav&profile=imagegen`，并以保留现有查询参数的原生回归覆盖。设备第 8 轮的中文远场麦克风用例列为用户终止的验收项，不计为成功；中文文字、英文文字和英文近场麦克风均有真实新任务和完整下载证据。一个缺少校验行的语音截图未发布，保留原始记录，不补造截图。最终验收报告同时保存这些边界与原始失败报告。通话静音仍由用户手动验收。


## 桌面文件夹与连续拖动修复（2026-10-31）

文件夹使用暖灰色立体托盘、九宫格小图标预览、浅色展开面板。桌面长按 600 ms 开始编辑，视觉中心进入目标后停留 350 ms 可合并；58 px 进入与 78 px 保持范围抵抗轻微手抖，独立提示框不改变目标图标的几何尺寸。快速松手仍紧凑换位。整个文件夹沿用应用拖动、左右边缘翻页和首尾循环。

文件夹内部每页 9 个应用，左右滑动翻页，长按进入排序；排序状态由应用拖动接管手势，边缘停留 500 ms 移入前后页。松手后保存顺序，保留原控件并在保存失败时回滚。排序入口、应用启动和“移到桌面”各自独立，不再长按立即移出。单夹上限扩大为 64 个，旧 version 1 存储可直接读取；仍受全局设置区与编码长度检查保护，保存失败不会丢弃旧成员。

注册表的顺序修订不再触发整页销毁重建，只有实际应用目录/图标变化或文件夹预览变化才重建。主题引用在图标自身 DELETE 回调注销；删除单元时清除旧点击目标和定时器。保存与界面刷新期间拒绝新拖动，避免对旧目录进行新编辑；文件夹排序时也阻止系统切换手势抢占。

回归脚本包括 `test_desktop_drag.py` 的迟滞命中、计时回绕、9 格分页定位及真实目录比较，`test_desktop_folders.py` 的成员不变式、跨页重排、持久化与 64 成员边界。工程真机测试代码在 `folder_polish_probe.inc`，正式固件不编入。设备结果以 `output/folder-polish` 及正式发布目录中的实际报告为准。


运行时闪存操作改由已存在的内部 CPU0 IPC 任务执行，保留原私有 SRAM 栈与缓冲、GD 四字节指令、DSI 自主扫描保护和设置双日志格式。原路径只切换 SP，没有切换线程局部数据/调度上下文；完整的内部任务上下文避免缓存关闭期间再访问调用者的外存线程数据。非 SMP 路径不变。工程日志单独记录调用者与执行者的内存类型，正式固件移除该追踪。

`test_flash_dispatch.py` 编译生产传输/分派函数，在真实 pthread IPC 边界运行 160 次双调用者读写，并覆盖 IPC 内重入、地址/长度保护、上下文拒绝、分派失败和显示保护清理。参考 Espressif 的 [P4 外部内存约束](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-guides/external-ram.html) 与 [内部任务闪存分派方案](https://components.espressif.com/components/espressif/esp_flash_dispatcher/versions/1.0.3/readme)。本实现复用 NuttX 平台原有 IPC，不引入 FreeRTOS 组件。

定位直连改动已按用户要求合并；`gps_direct.inc`、定位头文件、专用请求回归测试和 `docs/hios_location_direct.md` 纳入同一构建清单。此前单独定位固件不是本次最终固件，真实覆盖限制见定位说明。

工程恢复旧桌面的入口另需显式 `HI_FOLDER_PROBE_RECOVERY=1`，仅本次任务的恢复构建启用；普通工程构建与正式固件不会把用户桌面回退到测试前的历史快照。正式通用源码同步清单不包含该会话专用快照。
