这比直接移植 WPE 更符合当前平台条件。WPE 官方目前只支持 Linux 系统，而 HiOS 工程使用 NuttX；把完整 WebKit 移植到这里，涉及大量系统与图形适配，项目规模和风险都不适合“轻量版”。[WPE 官方 FAQ](https://wpewebkit.org/about/faq.html)

### 技术选择

我会先以 **litehtml + LVGL** 为核心：

- **litehtml**：解析 HTML/CSS 并计算页面布局。
- **LVGL**：复用 HiOS 现有图形界面，负责文字、图形和图片绘制。
- **HiOS 网络/TLS 能力**：负责 HTTPS 请求和资源下载。
- **原生 C/C++ 浏览器模块**：连接网络、布局、绘制和触摸事件；浏览器 UI 仍使用当前 HiOS 的应用体系。

litehtml 的定位是轻量 HTML/CSS 引擎，绘图、字体和图片由宿主提供；它适合迷你浏览器或简单页面查看，但不适合作为完整现代浏览器引擎。[litehtml 官方仓库](https://github.com/litehtml/litehtml)

这个选择是**针对当前 RTOS 和硬件约束的最佳起步方案**，不代表它功能最全或兼容性最高。它不内置完整 JavaScript 引擎，复杂网站、登录页和现代 Web 应用可能无法正常工作。因此，产品应定位为网页阅读器，而不是通用浏览器。

### 开发步骤

1. **做只读平台核查**：确认当前应用的图形接口、网络/TLS API、触摸事件、字体和图片解码能力，避免重复造已有模块。
2. **搭最小浏览链路**：先实现输入固定网址、HTTPS 获取页面、HTML 解析、布局和 LVGL 绘制。
3. **接入基本交互**：链接点击、返回、刷新、滚动、加载中和错误提示。
4. **控制资源使用**：限制单页 HTML 和图片缓存，避免多标签；重点测量加载时间、峰值内存和低资源时的错误恢复。
5. **再决定功能边界**：确认原型可用后，再评估书签、搜索、Cookie、下载或 JavaScript 是否值得加入。

### 第一阶段验收目标

先选一组公开、结构简单的 HTTPS 页面，确认：

- 页面能通过 HTTPS 加载并显示中文、链接和图片。
- 触摸滚动和链接跳转可用。
- 加载失败、证书错误和内存不足时不会卡死系统。
- 页面加载时的内存峰值留在设备可承受范围内。

具体数值需要在实际板卡上测量，不能仅凭“32 MB PSRAM”推断浏览器一定跑得动。

### 主要风险与备选

- **依赖移植风险**：litehtml 及其 HTML 解析依赖需要适配当前交叉编译和运行环境。
- **显示性能风险**：720×720 页面重绘可能较慢，需限制图片尺寸和重绘区域。
- **网站兼容性风险**：无完整 JavaScript，动态站点不在首版承诺范围内。
- **安全维护风险**：TLS 证书验证、重定向和链接处理要遵守安全规则；网页内容需按不可信输入处理。

如果 litehtml 的集成或页面能力不足，下一档考虑 NetSurf 的布局/渲染核心，但它也需要适配 HiOS，而且 JavaScript 能力有限。WPE WebKit 只适合之后转向 Linux 平台时重新评估，不作为当前 RTOS 方案。

**如果你批准开始开发，我会先检查工程中的接口并做最小原型，不会一上来移植完整浏览器内核。**
